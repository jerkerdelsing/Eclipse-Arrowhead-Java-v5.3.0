\section{Overview}
\label{sec:overview}

This document describes the \texttt{gatekeeper\allowbreak{}Management} service, which provides read access to the neighbour clouds and relays the Gatekeeper knows and to its status.
It is produced by the Gatekeeper system \cite{gk-sysd} in service version 5.2.2.

The rest of this document is organized as follows.
In Section \ref{sec:operations}, we describe the abstract message operations provided by the service.
In Section \ref{sec:model}, we end the document by presenting the data types used by the mentioned operations.
The concrete interface is specified in the HTTP/TLS/JSON IDD \cite{gk-gatekeeperManagement-http-idd}.

\subsection{Significant Prior Art}

Successor of the Arrowhead 4.6 Gatekeeper management endpoints.

\subsection{How This Service Is Meant to Be Used}

LocalCloudManager shows the relay connection and the configured clouds.

\subsection{Important Delimitations and Dependencies}
\label{sec:delimitations}

Only LocalCloudManager and Sysop. The unregistered endpoints \texttt{POST /\allowbreak{}gatekeeper/\allowbreak{}mgmt/\allowbreak{}clouds}, \texttt{POST /\allowbreak{}gatekeeper/\allowbreak{}mgmt/\allowbreak{}relays} and \texttt{DELETE /\allowbreak{}gatekeeper/\allowbreak{}mgmt/\allowbreak{}clouds/\allowbreak{}\{operator\}/\allowbreak{}\{name\}} edit the configuration.

\section{Service Interface}
\label{sec:operations}

This section describes the interfaces to the \texttt{gatekeeper\allowbreak{}Management} service.
In particular, each subsection names an abstract operation, an input type and an output type, in that order.
The input type is named inside parentheses, while the output type is preceded by a colon.
Input and output types are only denoted when accepted or returned, respectively, by the interface in question.

All abstract data types named in this section are defined in Section \ref{sec:model}.
