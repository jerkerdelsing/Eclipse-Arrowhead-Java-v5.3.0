\section{Implementation}
\label{Implementation}

The implementation is located in \texttt{ah5-LocalCloudConfigurator-java} (artifact \texttt{arrowhead-\allowbreak{}localcloudconfigurator}, \texttt{localcloudconfigurator.\allowbreak{}jar}). The same JAR runs as the Arrowhead system (\texttt{serve}, default), as the host worker (\texttt{worker}) and as the retained command-line tools (\texttt{keygen}, \texttt{register}, \texttt{executor}, \texttt{plan}).

\subsection{Implementation language and tools}
\begin{itemize}
\item Java 21, Spring Boot 3.4 (Web, Security, Data JPA, Quartz), Log4j2 with the JDBC log table, MariaDB driver, BouncyCastle (ColonyOS signatures).
\item Eclipse Arrowhead common library as a private vendored source copy (\texttt{vendor/}).
\item Storage: MySQL 8.4 (private schema \texttt{ah\_\allowbreak{}localcloudconfigurator}); the host worker uses files.
\item Host worker: non-web Spring application with the JDK \texttt{HttpsServer}.
\end{itemize}

\subsubsection{Host worker}

The worker is started as \texttt{java -jar localcloudconfigurator.jar worker -{}-lcc.\ldots} by a per-user launchd service installed with \texttt{scripts/\allowbreak{}install-\allowbreak{}direct.\allowbreak{}py} (RunAtLoad, KeepAlive). It does not register in the ServiceRegistry; it is the configurator's local agent. Properties:

\texttt{lcc.\allowbreak{}worker.\allowbreak{}address}, \texttt{lcc.\allowbreak{}worker.\allowbreak{}port} & 127.0.0.1, 8493; a non-loopback address is refused at start-up. \\ \hline
\texttt{lcc.\allowbreak{}worker.\allowbreak{}ssl.\allowbreak{}key-\allowbreak{}store}, \texttt{trust-\allowbreak{}store}, \texttt{*-\allowbreak{}password} & Worker certificate \texttt{LocalCloudConfiguratorWorker} (PKCS12), cloud truststore; passwords from a 0600 config tree. \\ \hline
\texttt{lcc.\allowbreak{}worker.\allowbreak{}ssl.\allowbreak{}crl-\allowbreak{}file} & Cloud CRL for client certificates (optional, recommended). \\ \hline
\texttt{lcc.\allowbreak{}worker.\allowbreak{}allowed-\allowbreak{}clients} & \texttt{LocalCloudConfigurator}. \\ \hline
\texttt{lcc.\allowbreak{}worker.\allowbreak{}cloud-\allowbreak{}dir}, \texttt{lcc.\allowbreak{}worker.\allowbreak{}docker} & Cloud view (\texttt{compose.\allowbreak{}yaml}, \texttt{scripts}, \texttt{.env}), Docker CLI. \\ \hline
\texttt{lcc.\allowbreak{}worker.\allowbreak{}state}, \texttt{lcc.\allowbreak{}catalog.\allowbreak{}file} & File state (\texttt{active-\allowbreak{}deployment.\allowbreak{}json}, \texttt{deployments/}, \texttt{workflows/}), the worker's own catalog copy. \\ \hline

\subsection{Non functional properties implementation}

\subsubsection{Security}

Mutual TLS on 8492 and to the worker (SysD, Section Security); outsourced authentication and the access filter for every operation; security profile guard; DML-only database account; read-only root filesystem.

\subsubsection{Power management}

None. The \texttt{sysMonitor} \texttt{power} observation always reports line supply.

\subsubsection{Internal monitoring}

Logs to the console, a rolling file and the \texttt{logs} table; the worker logs to the console (launchd log files). sysMonitor observations every 30 s.

\subsubsection{Configuration}

Spring properties (SysD), secrets from \texttt{configtree:\allowbreak{}/\allowbreak{}run/\allowbreak{}secrets/}.

\subsection{Deployment}

\texttt{compose.yaml} (project \texttt{ah5-\allowbreak{}localcloudconfigurator}) runs \texttt{localcloudconfigurator} (image \texttt{arrowhead-\allowbreak{}localcloudconfigurator-\allowbreak{}standalone:\allowbreak{}5.2.2}, UID 10001, read-only root filesystem, port 8492 on the host's loopback by default, \texttt{host.\allowbreak{}docker.\allowbreak{}internal} mapped to the host) and \texttt{localcloudconfigurator-\allowbreak{}db} (MySQL 8.4.11 with TLS, internal network). \texttt{scripts/\allowbreak{}deploy.\allowbreak{}sh} puts both services into a cloud's Compose file and installs the worker; it changes a deployed cloud and is run only by an operator.

\subsection{Verification}

\texttt{mvn clean verify}: catalog, planner and runner tests; direct backend (persistence, no replay, single worker); deployment coordinator (guard across restarts, stale hash); a full-application MockMvc test of every \texttt{/api} route with identity and grant checks, size limit and strict JSON; a plan-to-deployment run against a worker over mutual TLS and refusal of a missing, foreign, wrongly named or revoked certificate; the security profile test. A gated test validates the schema against a fresh MySQL 8.4.11 container and checks the DML-only grants.
