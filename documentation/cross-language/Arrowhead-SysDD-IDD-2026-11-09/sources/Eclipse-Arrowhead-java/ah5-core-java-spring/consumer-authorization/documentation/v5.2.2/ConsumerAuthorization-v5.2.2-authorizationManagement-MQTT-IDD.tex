\section{Overview}
\label{sec:overview}

This document describes the \texttt{authorization\allowbreak{}Management} service interface of the ConsumerAuthorization system over MQTT, which provides operator management of authorization policies at the management level, and bulk evaluation of authorization questions.

It's implemented using protocol, encoding as stated in below table:
\begin{table}[ht!]
  \centering
  \begin{tabular}{|l|l|l|}
    \hline
    \rowcolor{gray!33} Profile type & Type & Version \\ \hline
    Transfer protocol & MQTT & 3.1.1 \cite{mqtt311} \\ \hline
    Data encryption & TLS & 1.3 \cite{rfc8446}, 1.2 \cite{rfc5246} \\ \hline
    Encoding & JSON & RFC 8259 \cite{rfc8259} \\ \hline
    Compression & N/A & - \\ \hline
    Semantics & N/A & - \\ \hline
    Ontology & N/A & - \\ \hline
  \end{tabular}
  \caption{Communication and semantics details used for the \texttt{authorization\allowbreak{}Management} service interface}
  \label{tab:comunication_semantics_profile}
\end{table}

This document provides the Interface Design Description IDD to the \textit{authorizationManagement -- Service Description} document \cite{ca-authorizationManagement-sd}.
The operations, their semantics and the data models are the same as in the HTTP/TLS/JSON IDD \cite{ca-authorizationManagement-http-idd}; this document specifies the MQTT binding.

The MQTT interface is offered only when the system runs with \texttt{mqtt.api.enabled=true}; it is then registered with the interface template \texttt{generic\_\allowbreak{}mqtts} (\texttt{generic\_\allowbreak{}mqtt} without TLS), the broker address and port (\texttt{mqtt.\allowbreak{}broker.\allowbreak{}address}, \texttt{mqtt.\allowbreak{}broker.\allowbreak{}port}) and the base topic \texttt{arrowhead/\allowbreak{}consumer-\allowbreak{}authorization/\allowbreak{}authorization/\allowbreak{}management/\allowbreak{}}. In the Arrowhead-test-cloud-java deployment the MQTT interfaces of the core systems are disabled.

\section{Service Operations}
\label{sec:operations}

The provider subscribes to one topic per operation, the base topic followed by the operation name:

\noindent\begin{longtable}{| p{5cm} | p{10.4cm} |} \hline
\rowcolor{gray!33} Operation & Request topic \\ \hline \endhead
\texttt{grant-\allowbreak{}policies} & \texttt{arrowhead/\allowbreak{}consumer-\allowbreak{}authorization/\allowbreak{}authorization/\allowbreak{}management/\allowbreak{}grant-\allowbreak{}policies} \\ \hline
\texttt{revoke-\allowbreak{}policies} & \texttt{arrowhead/\allowbreak{}consumer-\allowbreak{}authorization/\allowbreak{}authorization/\allowbreak{}management/\allowbreak{}revoke-\allowbreak{}policies} \\ \hline
\texttt{query-\allowbreak{}policies} & \texttt{arrowhead/\allowbreak{}consumer-\allowbreak{}authorization/\allowbreak{}authorization/\allowbreak{}management/\allowbreak{}query-\allowbreak{}policies} \\ \hline
\texttt{check-\allowbreak{}policies} & \texttt{arrowhead/\allowbreak{}consumer-\allowbreak{}authorization/\allowbreak{}authorization/\allowbreak{}management/\allowbreak{}check-\allowbreak{}policies} \\ \hline
\end{longtable}

A consumer publishes a request envelope (\mref{MqttRequestTemplate}) to the topic and receives the answer (\mref{MqttResponseTemplate}) on its own \texttt{responseTopic}. The \texttt{authentication} field carries the requester's identity according to the provider's authentication policy: \texttt{IDENTITY-TOKEN//<token>} (outsourced or internal policy), \texttt{SYSTEM//<name>} (declared policy) or the requester's X.509 certificate (certificate policy). The \texttt{status} of the response uses the HTTP status code numbers (200, 201, 204, 400, 401, 403, 404, 408, 423, 500, 503); on error the payload is an \mref{ErrorMessage}.

\begin{lstlisting}[caption={Request envelope.}]
{
  "traceId": "a1b2c3",
  "authentication": "IDENTITY-TOKEN//<token>",
  "responseTopic": "arrowhead/response/TemperatureDisplay/a1b2c3",
  "qosRequirement": 1,
  "params": {},
  "payload": {}
}
\end{lstlisting}

\begin{lstlisting}[caption={Response envelope.}]
{
  "status": 200,
  "traceId": "a1b2c3",
  "receiver": "TemperatureDisplay",
  "payload": {}
}
\end{lstlisting}

\subsection{Primitives}

\rowcolor{gray!33} Type & Description \\ \hline
\pdef{Array} & A JSON Array \cite{rfc8259}; \pref{Array}$<$A$>$ has elements of type A. \\ \hline

\pdef{AuthorizationPolicyType} & One of \texttt{ALL}, \texttt{WHITELIST}, \texttt{BLACKLIST}, \texttt{SYS\_\allowbreak{}METADATA} (JSON String). \\ \hline

\pdef{Boolean} & JSON Boolean, \texttt{true} or \texttt{false}. \\ \hline
\pdef{DateTime} & JSON String with an ISO 8601 UTC timestamp, e.g. \texttt{2026-10-22T12:00:00Z}. \\ \hline
\pdef{ExceptionType} & One of \texttt{ARROWHEAD}, \texttt{INVALID\_\allowbreak{}PARAMETER}, \texttt{AUTH}, \texttt{FORBIDDEN}, \texttt{DATA\_\allowbreak{}NOT\_\allowbreak{}FOUND}, \texttt{TIMEOUT}, \texttt{LOCKED}, \texttt{INTERNAL\_\allowbreak{}SERVER\_\allowbreak{}ERROR}, \texttt{EXTERNAL\_\allowbreak{}SERVER\_\allowbreak{}ERROR} (JSON String). \\ \hline
\pdef{Number} & JSON Number, an integer. \\ \hline
\pdef{Object} & JSON Object; \pref{Object}$<$A$>$ has string keys and values of type A. \\ \hline
\pdef{String} & JSON String. \\ \hline
\end{tabularx}
