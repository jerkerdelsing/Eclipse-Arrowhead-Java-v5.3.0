\section{Overview}
\label{sec:overview}

This document describes the \texttt{local\allowbreak{}Cloud\allowbreak{}Management} service interface of the LocalCloudManager system, which provides the operator console API of the local cloud: overview, registry and data views, orchestration rules, consumers, inter-cloud state, sysMonitor history and subscriptions, plant descriptions, logs and container lifecycle.

It's implemented using protocol, encoding as stated in below table:
\begin{table}[ht!]
  \centering
  \begin{tabular}{|l|l|l|}
    \hline
    \rowcolor{gray!33} Profile type & Type & Version \\ \hline
    Transfer protocol & HTTP & 1.1 \cite{rfc9112} \\ \hline
    Data encryption & TLS & 1.3 \cite{rfc8446}, 1.2 \cite{rfc5246} \\ \hline
    Encoding & JSON & RFC 8259 \cite{rfc8259} \\ \hline
    Compression & N/A & - \\ \hline
    Semantics & N/A & - \\ \hline
    Ontology & N/A & - \\ \hline
  \end{tabular}
  \caption{Communication and semantics details used for the \texttt{local\allowbreak{}Cloud\allowbreak{}Management} service interface}
  \label{tab:comunication_semantics_profile}
\end{table}

This document provides the Interface Design Description IDD to the \textit{localCloudManagement -- Service Description} document \cite{lcm-localCloudManagement-sd}.
For further details about how this service is meant to be used, please consult that document.

The rest of this document describes how to realize the \texttt{local\allowbreak{}Cloud\allowbreak{}Management} service
interface in detail. Both in terms of its operations (Section \ref{sec:operations}) and its information model (Section \ref{sec:model}).

\subsection{Interface registration}

LocalCloudManager listens on two connectors. The Arrowhead connector (port 8491, HTTPS with mutual TLS) is registered in the ServiceRegistry with the interface template \texttt{generic\_\allowbreak{}https} and policy \texttt{CERT\_\allowbreak{}AUTH}, base path \texttt{/\allowbreak{}api}. The console connector (port 8490, plain HTTP, published on the host's loopback address only) serves the browser console with the same routes plus the console-only ones; it is not registered. The \texttt{operations} property lists the operations below with their method and path relative to the base path (path values are appended to the registered path):

\subsection{Access}

\textbf{Arrowhead connector (8491).} A request needs the caller's client certificate and \texttt{Authorization:\allowbreak{} Bearer IDENTITY-\allowbreak{}TOKEN/\allowbreak{}/\allowbreak{}<token>} of the same system (common outsourced authentication filter; 401 otherwise, with the common error body \texttt{\{"errorMessage", "errorCode", "exceptionType", "origin"\}}). A registered operation is allowed for Sysop, the systems of \texttt{lcm.\allowbreak{}api.\allowbreak{}whitelist} and systems with a ConsumerAuthorization grant of the operation (403 otherwise); other \texttt{/api} paths only for Sysop and the whitelist. The console-only paths (\texttt{/api/\allowbreak{}session}, \texttt{/health}, the UI) are 404 there.

\begin{lstlisting}[label={lst:arrowhead},caption={An invocation on the Arrowhead connector.}]
GET /api/overview HTTP/1.1
Host: cloud-monitor-api:8491
Authorization: Bearer IDENTITY-TOKEN//<identity token>
\end{lstlisting}

\textbf{Console connector (8490).} \texttt{Host} and \texttt{Origin} must be allowed console names (403 \texttt{"Host or Origin is not an allowed console address"}; Origin \texttt{null} is refused); with a configured proxy secret, \texttt{/api} requests must carry \texttt{X-\allowbreak{}Console-\allowbreak{}Proxy} (403 \texttt{"Not forwarded by the console"}); without a configured password every \texttt{/api} request is 503. Every \texttt{/api} route except \texttt{/api/\allowbreak{}session} needs the session cookie \texttt{ah\_\allowbreak{}console} (401 \texttt{"Console login required"}). Other paths serve the static console (\texttt{index.html} for unknown paths). Responses carry \texttt{X-\allowbreak{}Frame-\allowbreak{}Options:\allowbreak{} DENY}, \texttt{Content-\allowbreak{}Security-\allowbreak{}Policy:\allowbreak{} frame-\allowbreak{}ancestors 'none'}, \texttt{X-\allowbreak{}Content-\allowbreak{}Type-\allowbreak{}Options:\allowbreak{} nosniff} and \texttt{Referrer-\allowbreak{}Policy:\allowbreak{} no-\allowbreak{}referrer}.

\section{Service Operations}
\label{sec:operations}

The interfaces of the \texttt{local\allowbreak{}Cloud\allowbreak{}Management} service, its operations, data models and implementation are provided below.
In particular, each subsection first names the HTTP method and path used to call the operation, after which it names the abstract operation from the \texttt{local\allowbreak{}Cloud\allowbreak{}Management} SD document, as well as input and output types. The examples use the console connector; on the Arrowhead connector the same request carries the identity token instead of the cookie.

For \texttt{POST}, \texttt{PUT}, \texttt{PATCH} and \texttt{DELETE} the header \texttt{X-Arrowhead-Action: confirm} is required (428 \texttt{"Missing action confirmation header"}). Request bodies are \texttt{application/json} and at most 64 KiB (larger: 500 \texttt{"Request body is too large"}; malformed: 500 \texttt{"Invalid JSON body"}); an empty body counts as \texttt{\{\}}. Responses are \texttt{application/json} with \texttt{Cache-Control: no-store}.
Errors of the routes are answered with \texttt{\{"error": "<text>"\}} and the status codes \texttt{400 Bad Request} (invalid input), \texttt{401 Unauthorized}, \texttt{403 Forbidden}, \texttt{404 Not Found} (\texttt{"Not found"} for an unknown route), \texttt{405 Method Not Allowed}, \texttt{409 Conflict} (stored entry changed since it was read), \texttt{415 Unsupported Media Type} (login without JSON), \texttt{428 Precondition Required}, \texttt{429 Too Many Requests} (login locked), \texttt{500 Internal Server Error}, \texttt{502 Bad Gateway} (a provider request failed) and \texttt{503 Service Unavailable} (no authorized provider found by orchestration, or no console password). An error of a provider is passed on with the provider's status and error message.

  "configured": true
}
\end{lstlisting}

\osubsection{login}{POST}{/\allowbreak{}api/\allowbreak{}session}{\mref{Login}}{}

Logs in with the console password. The body must be \texttt{application/json} (415 otherwise). On success the response sets \texttt{ah\_console=<token>; HttpOnly; SameSite=Strict; Path=/; Max-Age=28800}. A wrong password is 401 \texttt{\{"error": "Wrong password"\}}; a locked client is 429 with \texttt{Retry-After} and \texttt{\{"error": "Too many failed logins; try again later"\}}. Other methods on this path are 405. Console connector only.

A successful call returns \texttt{204 No Content}.

\begin{lstlisting}[label={lst:login},caption={An \oref{login} invocation.}]
POST /api/session HTTP/1.1
Host: 127.0.0.1:8490
Content-Type: application/json

{
  "password": "<console password>"
}
\end{lstlisting}

\section{Data Models}
\label{sec:model}

Here, all data objects that can be part of the service calls associated with this service are listed in alphabetic order.
Note that each subsection, which describes one type of object, begins with the \textit{struct} keyword, which is meant to denote a JSON \pref{Object} that must contain certain fields, or names, with values conforming to explicitly named types.
Fields that are not needed may be omitted or \texttt{null} in requests; empty fields are omitted in responses.
As a complement to the primary types defined in this section, there is also a list of secondary types in Section \ref{sec:model:primitives}, which are used to represent things like hashes, identifiers and texts.
