\section{Overview}
\label{sec:overview}

This document describes the \texttt{local\allowbreak{}Cloud\allowbreak{}Management} service, which provides the operator console API of the local cloud: overview, registry and data views, orchestration rules, consumers, inter-cloud state, sysMonitor history and subscriptions, plant descriptions, logs and container lifecycle.
It is produced by the LocalCloudManager system \cite{lcm-sysd} in service version 1.0.0.

The rest of this document is organized as follows.
In Section \ref{sec:operations}, we describe the abstract message operations provided by the service.
In Section \ref{sec:model}, we end the document by presenting the data types used by the mentioned operations.
The concrete interface is specified in the HTTP/TLS/JSON IDD \cite{lcm-localCloudManagement-http-idd}.

\subsection{Significant Prior Art}

New in this workspace.

\subsection{How This Service Is Meant to Be Used}

The browser console, served by LocalCloudManager on its console connector (8490, host loopback), calls the operations after the operator has logged in with the console password. Arrowhead systems call the same operations on the Arrowhead connector (8491) with their certificate and identity token. Each view is assembled on request from the providing systems with LocalCloudManager\'s own identity.

\subsection{Important Delimitations and Dependencies}
\label{sec:delimitations}

Registered with \texttt{generic\_\allowbreak{}https} and policy \texttt{CERT\_\allowbreak{}AUTH} on the Arrowhead connector: there a caller needs its client certificate and an identity token of the same system, and the operation is allowed for Sysop, the systems of \texttt{lcm.\allowbreak{}api.\allowbreak{}whitelist} and systems with a ConsumerAuthorization grant of the operation. On the console connector the console session authenticates instead; \texttt{session}, \texttt{login} and \texttt{logout} exist only there and are not registered. Changing requests need \texttt{X-\allowbreak{}Arrowhead-\allowbreak{}Action:\allowbreak{} confirm} (428 otherwise). The registered operation names are camelCase, which deviates from the kebab-case convention of ARROWHEAD-NAMING.md.

\section{Service Interface}
\label{sec:operations}

This section describes the interfaces to the \texttt{local\allowbreak{}Cloud\allowbreak{}Management} service.
In particular, each subsection names an abstract operation, an input type and an output type, in that order.
The input type is named inside parentheses, while the output type is preceded by a colon.
Input and output types are only denoted when accepted or returned, respectively, by the interface in question.

All abstract data types named in this section are defined in Section \ref{sec:model}.

The following interface operations are available.

\osubsection{session}{}{\mref{Session}}

Returns whether the console session is valid (no session needed; console connector only, not registered).

\osubsection{login}{\mref{Login}}{}

Logs in with the console password; sets the HttpOnly, SameSite=Strict session cookie (console connector only, not registered).

\osubsection{logout}{}{}

Ends the console session (console connector only, not registered).

\osubsection{overview}{}{\mref{View}}

Overview: containers, registered systems, brokers, sysMonitor flows, activity.

\osubsection{serviceRegistryManagement}{}{\mref{View}}

Registry inventory: devices, systems, services and interface templates.

\osubsection{dataManager}{}{\mref{View}}

DataManager historian streams and recent records.

\osubsection{consumers}{}{\mref{View}}

Per provider service, the authorized and the orchestrated consumers.

\osubsection{interCloud}{}{\mref{View}}

Relay connection, Gatekeeper and GateTunnel sessions.

\osubsection{sysMonitorHistory}{}{\mref{View}}

Monitored systems and their history.

\osubsection{sysMonitorSubscriptions}{}{\mref{View}}

SysMonitor providers, subscriptions and intake state.

\osubsection{subscribeSysMonitor}{\mref[Sys\allowbreak{}Monitor\allowbreak{}Subscription\allowbreak{}Request]{SysMonitorSubscriptionRequest}}{\mref{View}}

Sets the SysMonitor subscription of a provider (appended to the path).

\osubsection{unsubscribeSysMonitor}{\pref{Name}}{}

Removes the SysMonitor subscription of a provider.

\osubsection{plantDescriptions}{}{\mref{View}}

Plant descriptions with the registered systems and services offered as choices.

\osubsection{createPlantDescription}{\mref{PlantDescription}}{\mref{PlantDescription}}

Creates a plant description in the Plant\allowbreak{}Description\allowbreak{}Engine.

\osubsection{replacePlantDescription}{\mref{PlantDescription}}{\mref{PlantDescription}}

Replaces a plant description (identifier appended).

\osubsection{updatePlantDescription}{\mref{PlantDescription}}{\mref{PlantDescription}}

Updates a plant description (identifier appended).

\osubsection{removePlantDescription}{\pref{Identifier}}{}

Removes a plant description (identifier appended).

\osubsection{orchestrationRules}{}{\mref{View}}

SimpleStore rules and the dynamic orchestrations of Dynamic\allowbreak{}Service\allowbreak{}Orchestration.

\osubsection{createOrchestrationRule}{\mref{OrchestrationRule}}{\mref{View}}

Creates a SimpleStore rule.

\osubsection{removeOrchestrationRule}{\pref{Identifier}}{}

Removes a SimpleStore rule (identifier appended).

\osubsection{logs}{}{\mref{LogLines}}

Log lines of a container of the cloud.

\osubsection{lifecycle}{\pref{String}}{\mref{LifecycleResult}}

Starts, stops or restarts a managed container: \texttt{POST /\allowbreak{}api/\allowbreak{}containers/\allowbreak{}\textless{}service\textgreater{}/\allowbreak{}\textless{}action\textgreater{}}.

\subsection*{Console operations outside the registered operation list}

The console API also offers the following operations. They are not part of the \texttt{operations} property registered in the ServiceRegistry (the console is their consumer); they are served on both connectors with the same access rules as the registered operations (on the Arrowhead connector only for Sysop and \texttt{lcm.\allowbreak{}api.\allowbreak{}whitelist}, since no grant can name them) and, for changes, need the confirmation header.

\osubsection{features}{}{\mref{Features}}

Which optional console views are enabled.

\osubsection{authorizationPolicies}{}{\mref{PolicyView}}

Local-cloud management policies of Consumer\allowbreak{}Authorization (editable) and provider-owned local policies (read-only).

\osubsection{grantAuthorizationPolicy}{\mref{PolicyChange}}{\mref{ManagementPolicy}}

Grants a local management policy, or replaces the policy of the same provider and target when \texttt{expected} matches the stored one. Provider and service must be registered in the local cloud; policy types are \texttt{ALL}, \texttt{WHITELIST} and \texttt{BLACKLIST}.

\osubsection{revokeAuthorizationPolicy}{\mref{PolicyChange}}{\mref{Removal}}

Revokes a local management policy (instance identifier appended to the path) when \texttt{expected} matches the stored policy.

\osubsection{changeOrchestrationRulePriority}{\mref{RulePriorityChange}}{\mref{View}}

Changes the priority of a SimpleStore rule (identifier appended) with SimpleStore \texttt{modify-\allowbreak{}priorities}, or by create and remove when \texttt{ORCHESTRATION\_\allowbreak{}PRIORITY\_\allowbreak{}MODE=replace}.

\osubsection{sosConfigurations}{}{\mref{View}}

SoS compositions (plant descriptions of the Plant\allowbreak{}Description\allowbreak{}Engine); one composition when its identifier is appended.

\osubsection{createSoS}{\mref{SoSChange}}{\mref{PlantDescription}}

Stores a validated SoS composition (unique systems and ports, required-to-provided connections, included compositions without cycles).

\osubsection{replaceSoS}{\mref{SoSChange}}{\mref{PlantDescription}}

Replaces an SoS composition (identifier appended) when \texttt{expected} matches the stored one.

\osubsection{removeSoS}{\mref{SoSChange}}{\mref{Removal}}

Removes an SoS composition (identifier appended) when \texttt{expected} matches the stored one.

\osubsection{localCloudConfiguration}{\pref{String}}{\mref{View}}

Local-cloud configuration view (404 when \texttt{lcm.\allowbreak{}local-\allowbreak{}cloud-\allowbreak{}configuration.\allowbreak{}enabled=\allowbreak{}false}): the route below \texttt{/api/\allowbreak{}localcloud} selects one operation of the \texttt{local\allowbreak{}Cloud\allowbreak{}Configuration} service of LocalCloudConfigurator \cite{lcc-localCloudConfiguration-sd}, which is consumed through orchestration with LocalCloudManager\'s certificate and identity token: \texttt{GET} of \texttt{/catalog}, \texttt{/status}, \texttt{/configurations}, \texttt{/configurations/\{uuid\}} and \texttt{/deployments/\{id\}}; \texttt{POST} of \texttt{/plan}, \texttt{/deployments} and \texttt{/configurations}; \texttt{PUT} and \texttt{DELETE} of \texttt{/configurations/\{uuid\}}. Status and body of the configurator are returned unchanged; other routes are 404.

\osubsection{chipletFloorplans}{\pref{String}}{\mref{View}}

Chiplet floorplan view when \texttt{lcm.\allowbreak{}chiplet-\allowbreak{}floorplans.\allowbreak{}enabled=\allowbreak{}true} (404 otherwise), through orchestrated Chiplet\allowbreak{}Floorplan\allowbreak{}Generator services: \texttt{GET} list (\texttt{page}, \texttt{size} up to 200), \texttt{/library} and \texttt{/\{id\}}; \texttt{POST} create (stored inactive, 201) and \texttt{POST /check-network}; \texttt{PUT /\{id\}} with \texttt{expectedUpdatedAt} (409 when changed); \texttt{DELETE /\{id\}}. Bodies carry \texttt{floorplan} with 1--64 chiplets and at most 1024 links.
