\section{Overview}
\label{sec:overview}

This document describes the LocalCloudManager system. LocalCloudManager is the operator console of the local cloud: it shows the state of the cloud and carries out the management actions an operator starts, with its own Arrowhead identity.

\subsection{How This System Is Meant to Be Used}
\label{sec:use}

The operator opens the console (\texttt{http:\allowbreak{}/\allowbreak{}/\allowbreak{}127.\allowbreak{}0.\allowbreak{}0.\allowbreak{}1:\allowbreak{}8490}), logs in with the console password and works in the views (overview, registry, orchestration rules and authorization policies, plant descriptions, SoS composition, consumers, data, sysMonitor, inter-cloud, runtime and, when enabled, local-cloud configuration and chiplet floorplans).

\subsection{System functionalities and properties}
\label{sec:properties}

\subsubsection{Functional properties of the system}

\begin{itemize}
  \item Views assembled from the core and support systems.
  \item Orchestration rules (create, remove, change priority), plant descriptions and sysMonitor subscriptions.
  \item Local-cloud management authorization policies of ConsumerAuthorization (view, grant, replace, revoke), with optimistic concurrency on the expected policy snapshot.
  \item System-of-Systems (SoS) compositions, stored as plant descriptions in the Plant\allowbreak{}Description\allowbreak{}Engine; saving an active SoS needs an explicit confirmation because it changes orchestration.
  \item Optional graphical local-cloud configuration through the Local\allowbreak{}Cloud\allowbreak{}Configurator (catalog, saved designs, plans and reviewed deployments) when \texttt{LOCAL\_\allowbreak{}CLOUD\_\allowbreak{}CONFIGURATOR\_\allowbreak{}URL} is set.
  \item Optional chiplet floorplan editing through the Chiplet\allowbreak{}Floorplan\allowbreak{}Generator (orchestrated) when \texttt{CHIPLET\_\allowbreak{}FLOORPLANS\_\allowbreak{}ENABLED=\allowbreak{}true}.
  \item Container logs and lifecycle through the Docker proxy.
  \item Native sysMonitor observations.
\end{itemize}

Secrets (identity password, console password hash, console proxy secret, configurator token, private key) have no usable defaults; the standalone deployment reads them from per-deployment Compose file secrets (\texttt{*\_FILE} variables) under \texttt{/\allowbreak{}run/\allowbreak{}secrets}.

\subsubsection{Data stored by the system}

None durable; sessions and the identity token in memory. SoS compositions are stored by the Plant\allowbreak{}Description\allowbreak{}Engine, policies by Consumer\allowbreak{}Authorization and designs by the Local\allowbreak{}Cloud\allowbreak{}Configurator.

\subsubsection{Non functional properties}

A failing provider gives a partial view with an error note.

\subsubsection{Stateful or stateless}

Stateless apart from sessions.

\subsection{Important Delimitations}
\label{sec:delimitations}

Acts only within the grants given to LocalCloudManager (not a sysop since J23).

\section{Security}
\label{sec:security}

LocalCloudManager is a Node.js console, not a Spring system. Towards the cloud it always uses HTTPS with its X.509 certificate following the Arrowhead certificate profile (\texttt{LocalCloudManager.<Cloud>.<Organization>.arrowhead.eu}); provider certificates not issued under the cloud CA, or revoked in its CRL, are refused. The operator side is plain HTTP on the host's loopback address through the console's nginx. The standalone deployment of this folder (\texttt{compose.yaml}) runs this configuration.

\subsection{Security model}


\begin{itemize}
  \item \textbf{Protocols:} HTTPS (TLS 1.3 and 1.2) with its client certificate towards the cloud; AMQP over TLS for \texttt{sysMonitor}; plain HTTP between the browser, nginx and the API on the loopback address and the console's own networks.
  \item \textbf{Data protection:} transport encryption by TLS towards the cloud; no database. Secrets are kept out of the container environment (Compose file secrets).
  \item \textbf{Operator authentication:} console password (scrypt hash), HttpOnly SameSite=Strict session cookie, lock-out after repeated failures, allowed host names.
  \item \textbf{Towards the cloud:} mutual TLS with the LocalCloudManager certificate and an identity token bound to it; rights are exactly the grants given to LocalCloudManager.
  \item Console access: only requests forwarded by the console's nginx (proxy secret), allowed host names (against DNS rebinding), scrypt-hashed password, JSON-only login, HttpOnly SameSite=Strict session cookie, per-client lock-out after five wrong passwords, \texttt{X-\allowbreak{}Arrowhead-\allowbreak{}Action:\allowbreak{} confirm} on changes and expected-snapshot checks (409) for policy, rule-priority, SoS and floorplan edits. Docker only through the proxy.
\end{itemize}

For the Arrowhead certificate profile see github.com/eclipse-arrowhead/documentation.
