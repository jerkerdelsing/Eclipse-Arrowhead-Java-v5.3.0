\section{Overview}
\label{sec:overview}

This document describes the LocalCloudManager system. LocalCloudManager is the operator console of the local cloud: it shows the state of the cloud and carries out the management actions an operator starts, with its own Arrowhead identity.

\subsection{How This System Is Meant to Be Used}
\label{sec:use}

The operator opens the console on the console connector (\texttt{http:\allowbreak{}/\allowbreak{}/\allowbreak{}127.\allowbreak{}0.\allowbreak{}0.\allowbreak{}1:\allowbreak{}8490}), logs in with the console password and works in the views (overview, registry, orchestration rules and authorization policies, plant descriptions, SoS composition, consumers, data, sysMonitor, inter-cloud, runtime and, when enabled, local-cloud configuration and chiplet floorplans).

\subsection{System functionalities and properties}
\label{sec:properties}

\subsubsection{Functional properties of the system}

\begin{itemize}
  \item Views assembled from the core and support systems.
  \item Orchestration rules (create, remove, change priority), plant descriptions and sysMonitor subscriptions.
  \item Local-cloud management authorization policies of ConsumerAuthorization (view, grant, replace, revoke), with optimistic concurrency on the expected policy snapshot.
  \item System-of-Systems (SoS) compositions, stored as plant descriptions in the Plant\allowbreak{}Description\allowbreak{}Engine; saving an active SoS needs an explicit confirmation because it changes orchestration.
  \item Optional graphical local-cloud configuration through the Local\allowbreak{}Cloud\allowbreak{}Configurator (catalog, saved designs, plans and reviewed deployments), consumed as the Arrowhead service \texttt{local\allowbreak{}Cloud\allowbreak{}Configuration} through orchestration; switched off with \texttt{lcm.\allowbreak{}local-\allowbreak{}cloud-\allowbreak{}configuration.\allowbreak{}enabled=\allowbreak{}false}.
  \item Optional chiplet floorplan editing through the Chiplet\allowbreak{}Floorplan\allowbreak{}Generator (orchestrated) when \texttt{lcm.\allowbreak{}chiplet-\allowbreak{}floorplans.\allowbreak{}enabled=\allowbreak{}true}.
  \item Container list, logs and lifecycle through the separate Docker proxy.
  \item The same views and actions for Arrowhead systems on the Arrowhead connector (\texttt{local\allowbreak{}Cloud\allowbreak{}Management}), for Sysop, whitelisted systems and systems with a ConsumerAuthorization grant.
  \item Native sysMonitor observations (common publisher) and \texttt{general\allowbreak{}Management} \texttt{get-\allowbreak{}config}.
\end{itemize}

Secrets (store password, identity password, console password hash) have no usable defaults; they are Compose file secrets read through \texttt{configtree:\allowbreak{}/\allowbreak{}run/\allowbreak{}secrets/}.

\subsubsection{Data stored by the system}

None durable: the system has no database. Console sessions, the identity token, orchestration results and the overview history are kept in memory. SoS compositions are stored by the Plant\allowbreak{}Description\allowbreak{}Engine, policies by Consumer\allowbreak{}Authorization and designs by the Local\allowbreak{}Cloud\allowbreak{}Configurator.

\subsubsection{Non functional properties}

A failing provider gives a partial view with an error note.

\subsubsection{Stateful or stateless}

Stateless apart from sessions.

\subsection{Important Delimitations}
\label{sec:delimitations}

Acts only within the grants given to LocalCloudManager (not a sysop since J23). The console connector must not be exposed beyond the host: it is plain HTTP, authenticated by the console password only. Docker is reached only through the proxy, whose allowlist limits the console to listing, logs and the lifecycle of managed services of its own Compose project.

\section{Security}
\label{sec:security}

LocalCloudManager is a Java-Spring support system with two connectors in one process. The Arrowhead connector (8491) uses HTTPS with mutual TLS and the X.509 certificate following the Arrowhead certificate profile (\texttt{LocalCloudManager.<Cloud>.<Organization>.arrowhead.eu}). Towards providers it uses the same certificate and an identity token bound to it; provider certificates not issued under the cloud CA, or revoked in its CRL, are refused. The console connector (8490) is plain HTTP, published on the host's loopback address only, for the operator's browser. The standalone deployment of this folder (\texttt{compose.yaml}) runs this configuration.

\subsection{Security model}

\begin{itemize}
  \item \textbf{Protocols:} HTTPS (TLS 1.3 and 1.2) with mutual TLS on 8491 and towards the cloud; AMQP over TLS (SASL EXTERNAL) for \texttt{sysMonitor}; plain HTTP on the console connector (host loopback) and between the console process and the Docker proxy (internal network).
  \item \textbf{Security profile:} the common security profile guard refuses to start the system with TLS disabled, declared identities or the authorization check switched off, unless the \texttt{development} profile is selected explicitly.
  \item \textbf{Data protection:} transport encryption by TLS towards the cloud; no database; secrets as Compose file secrets, never in the environment or on the command line; read-only root filesystem, UID 10001, no capabilities.
  \item \textbf{Arrowhead callers (8491):} client certificate and identity token of the same system (outsourced authentication); \texttt{local\allowbreak{}Cloud\allowbreak{}Management} for Sysop, \texttt{lcm.\allowbreak{}api.\allowbreak{}whitelist} and systems with a ConsumerAuthorization grant of the operation (fail closed); \texttt{general\allowbreak{}Management} for Sysop only.
  \item \textbf{Operator (8490):} console password (scrypt hash, N=16384, r=8, p=1), JSON-only login, HttpOnly SameSite=Strict session cookie checked by Spring Security (stateless), per-client lock-out after five wrong passwords within five minutes (60 s, doubling to at most 15 minutes), allowed Host and Origin names (against DNS rebinding), optional proxy secret, \texttt{X-\allowbreak{}Arrowhead-\allowbreak{}Action:\allowbreak{} confirm} on changes and expected-snapshot checks (409) for policy, rule-priority, SoS and floorplan edits. Console requests bypass the Arrowhead filters; they act with LocalCloudManager's own grants.
  \item \textbf{Privilege separation:} the console process holds no Docker socket. The separate Docker proxy forwards only \texttt{GET /\allowbreak{}containers/\allowbreak{}json} (filtered to its Compose project), \texttt{GET /\allowbreak{}containers/\allowbreak{}<id>/\allowbreak{}logs} of a project container and \texttt{POST /\allowbreak{}containers/\allowbreak{}<id>/\allowbreak{}start|stop|restart} of a project container in \texttt{MANAGED\_\allowbreak{}SERVICES}; everything else is answered 403.
\end{itemize}

For the Arrowhead certificate profile see github.com/eclipse-arrowhead/documentation.
