# LocalCloudManager 5.2.2

> Current independent console deployment: see [DEPLOYMENT.md](DEPLOYMENT.md). This is Node.js/nginx; no Java JAR applies. The local Compose definition has no host Docker access. Existing combined-cloud integration notes below are historical context.

Operator console of an Arrowhead 5.2.2 local cloud. It shows the cloud's state (containers, registry, orchestration,
consumers, DataManager data, SysMonitor history, inter-cloud exchange) and carries out operator actions (orchestration
rules, plant descriptions, sysMonitor subscriptions, container logs and lifecycle). It acts in the cloud with its own system
certificate `LocalCloudManager.<Cloud>.<Organization>.arrowhead.eu` and an identity token bound to it.

Despite the folder, it is not a Java system: the API and the Docker proxy are Node.js 20, the UI is static HTML/JS served by nginx.

| Folder | Container | Content |
|---|---|---|
| `api/` | `cloud-monitor-api` (port 8491) | `src/server.js` (routes, Arrowhead clients, registration), `src/console-auth.js` (console login), `src/sysmonitor.js` (native sysMonitor over AMQP); tests in `test/` |
| `ui/` | `cloud-monitor-ui` (port 8490) | `public/index.html`, `app.js`, `styles.css`; `nginx.conf` forwards `/api/` to the API |
| `docker-proxy/` | `docker-proxy` | Docker Engine API subset for the console (container list, logs, lifecycle of `MANAGED_SERVICES`) |
| `documentation/v5.2.2/` | | SysD, SysDD, `localCloudManagement` SD and HTTP IDD, `sysMonitor` SD and AMQP IDD (LaTeX, Arrowhead template, generated by `../documentation-tools`) |

Produced services: `localCloudManagement` 1.0.0 (console API, `generic_http`, policy `NONE`: the console session
authenticates) and `sysMonitor` 1.0.0 (`generic_amqps`, `CERT_AUTH`).

## Deployment

Both test clouds build these folders (`../Arrowhead-test-cloud/compose.yaml`, `../Arrowhead-test-cloud-go/compose.yaml`):

```yaml
cloud-monitor-api:
  build:
    context: ../ah5-support-java-spring/LocalCloudManager/api
```

The console is published on `127.0.0.1:8490` (TestCloud) and `127.0.0.1:9490` (GoCloud) and needs the console password
(`CONSOLE_PASSWORD_HASH`, set by the clouds' `scripts/rotate-secrets.sh`). Its cloud rights are the grants listed in the SysDD.
