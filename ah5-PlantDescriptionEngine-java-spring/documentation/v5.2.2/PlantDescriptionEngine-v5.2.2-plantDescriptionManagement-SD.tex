\section{Overview}
\label{sec:overview}

This document describes the \texttt{plant\allowbreak{}Description\allowbreak{}Management} service, which provides management of plant descriptions: the engineered systems of the plant, the services they consume and produce (ports), and the connections between ports.
It is produced by the PlantDescriptionEngine system \cite{pde-sysd} in service version 1.0.0.

The rest of this document is organized as follows.
In Section \ref{sec:operations}, we describe the abstract message operations provided by the service.
In Section \ref{sec:model}, we end the document by presenting the data types used by the mentioned operations.
The concrete interface is specified in the HTTP/TLS/JSON IDD \cite{pde-plantDescriptionManagement-http-idd}.

\subsection{Significant Prior Art}

Successor of the Arrowhead 4.6 Plant\allowbreak{}Description\allowbreak{}Engine management service.

\subsection{How This Service Is Meant to Be Used}

Engineers and LocalCloudManager create, replace, update, activate and remove plant descriptions. One description (with its includes) is active; its connections become a managed provider snapshot in Dynamic\allowbreak{}Service\allowbreak{}Orchestration.

\subsection{Important Delimitations and Dependencies}
\label{sec:delimitations}

Descriptions are validated (includes, unique systems, ports and connections, naming). Requires the local DSO service\allowbreak{}Orchestration\allowbreak{}Plant\allowbreak{}Management extension. PDE atomically replaces its complete snapshot; unresolved producers retain empty scopes, and DSO applies its normal security checks. Access follows the management policy (standalone deployment: \texttt{sysop-\allowbreak{}only}; LocalCloudManager needs the whitelist policy with \texttt{management.\allowbreak{}whitelist=\allowbreak{}LocalCloudManager}).

\section{Service Interface}
\label{sec:operations}

This section describes the interfaces to the \texttt{plant\allowbreak{}Description\allowbreak{}Management} service.
In particular, each subsection names an abstract operation, an input type and an output type, in that order.
The input type is named inside parentheses, while the output type is preceded by a colon.
Input and output types are only denoted when accepted or returned, respectively, by the interface in question.

All abstract data types named in this section are defined in Section \ref{sec:model}.

  \label{fig:SD}

The following interface operations are available.

\osubsection{query}{}{\mref[Plant\allowbreak{}Description\allowbreak{}List\allowbreak{}Response]{PlantDescriptionListResponse}}

Returns a page of plant descriptions, optionally only the active one.

\osubsection{get}{\pref{Identifier}}{\mref{PlantDescriptionResponse}}

Returns a plant description.

\osubsection{create}{\mref{PlantDescriptionRequest}}{\mref{PlantDescriptionResponse}}

Creates a plant description; if active, it replaces the active one and the rules are synchronized.

\osubsection{replace}{\mref{PlantDescriptionRequest}}{\mref{PlantDescriptionResponse}}

Replaces a plant description.

\osubsection{update}{\mref{PlantDescriptionUpdate}}{\mref{PlantDescriptionResponse}}

Changes the given fields of a plant description.

\osubsection{remove}{\pref{Identifier}}{}

Removes a plant description and its rules.
