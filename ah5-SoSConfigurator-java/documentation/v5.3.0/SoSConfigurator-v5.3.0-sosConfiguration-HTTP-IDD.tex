\section{Request and response data models}
\paragraph{SosRequest.} \path|name| is a string; \path|clouds| is an array of member-cloud strings; \path|exchanges| is an array of Exchange records; \path|verifyDiscovery| is a boolean. Null clouds/exchanges are exposed as empty lists by model helpers and then evaluated by policy. Exchange has string fields \path|consumerCloud|, \path|consumer|, \path|providerCloud|, \path|provider|, \path|service|, and a string array \path|operations|. Policies determine whether the named members, partners and operation set are allowed.

\paragraph{Plan.} Fields are \path|sos|, \path|members|, \path|allowed|, \path|violations|, \path|steps|, \path|notes| and \path|evaluation|. A Step contains \path|kind|, \path|role| and \path|target|. The evaluation retains catalog-derived cloud configuration. A refused plan has no executable step list. A submission response includes the plan and the returned workflow identifier; it does not assert workflow completion.

\paragraph{Catalog.} Top-level fields are \path|organization|, \path|colony|, \path|relay|, \path|forbiddenConsumers| and \path|clouds|. Cloud records include organization/implementation, executor role, inter-cloud capability, service ports, approved consumers and exports. The catalog is the policy authority; it is not an arbitrary request-provided configuration.

\paragraph{Status and submissions.} Status returns \path|relay| and a \path|clouds| map. An executor I/O failure becomes an object with \path|state=offline| and \path|error| rather than failing every executor's observation. Submission-list rows contain \path|id|, \path|sos|, \path|submittedBy| and \path|submittedAt|. Workflow/process state is returned by the ColonyOS adapter; it is not replaced by the local submission record.
\section{Validation, errors and asynchronous behavior}
Missing, empty or invalid JSON request bodies give 400 with an \path|error| string. Bodies exceeding 65536 bytes give 413. A plan that violates policies is returned with 200 by the plan operation; submitting that plan gives 422 with \path|error| and \path|plan|. Submission/backend I/O errors give 502. A deployment identifier not matching 64 lowercase hexadecimal characters gives 404. Authentication/authorization filters can reject requests earlier with 401/403. Unknown routes and console-only paths on the Arrowhead connector are not service operations.

All response objects are serialized with the system mapper; omitted null fields and source record types remain significant. A timeout or local database error after remote workflow creation can require operator reconciliation. No idempotency or exactly-once guarantee is introduced by these interfaces.
\section{Console-only endpoint}
\path|POST /api/session| performs browser console login and manages the \path|ah_sos_console| session cookie under console-specific controls. It is not registered as a \path|sosConfiguration| service operation and is not an Arrowhead identity login. UI/session paths exist only on the console connector; consumers of the registered service must use the Arrowhead identity/security model.
\section{Security and access model}
The secure Arrowhead connector uses TLS with client certificates, outsourced identity verification and token-to-certificate binding. \path|SosAccessFilter| permits a \path|sosConfiguration| operation for a verified Sysop, a named \path|sos.api.whitelist| system or a ConsumerAuthorization operation grant. An authenticated identity alone is insufficient. General management remains governed by the common management filter.

The separate console authenticates a browser with a configured scrypt password hash and the \path|ah_sos_console| cookie. It applies Host/Origin checks and session/lockout rules. A console session does not become an Arrowhead identity token. Static UI/session paths are console-only; the Arrowhead connector returns 404 for them. Console handling marks authenticated operator requests so the internal API can execute without pretending to be an mTLS system caller.
