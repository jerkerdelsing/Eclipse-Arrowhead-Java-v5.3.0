\section{Overview}
\label{sec:overview}

This document describes the \texttt{certificateSigning} service interface of the CertificateAuthority system, which provides signing of proof-of-possession certificate requests with the local-cloud CA, under the Arrowhead certificate profiles.

It's implemented using protocol, encoding as stated in below table:
\begin{table}[ht!]
  \centering
  \begin{tabular}{|l|l|l|}
    \hline
    \rowcolor{gray!33} Profile type & Type & Version \\ \hline
    Transfer protocol & HTTP & 1.1 \cite{rfc9112} \\ \hline
    Data encryption & TLS & 1.3 \cite{rfc8446}, 1.2 \cite{rfc5246} \\ \hline
    Encoding & JSON & RFC 8259 \cite{rfc8259} \\ \hline
    Compression & N/A & - \\ \hline
    Semantics & N/A & - \\ \hline
    Ontology & N/A & - \\ \hline
  \end{tabular}
  \caption{Communication and semantics details used for the \texttt{certificateSigning} service interface}
  \label{tab:comunication_semantics_profile}
\end{table}

This document provides the Interface Design Description IDD to the \textit{certificateSigning -- Service Description} document \cite{cau-certificateSigning-sd}.
For further details about how this service is meant to be used, please consult that document.

The rest of this document describes how to realize the \texttt{certificateSigning} service
interface in detail. Both in terms of its operations (Section \ref{sec:operations}) and its information model (Section \ref{sec:model}).

\subsection{Interface registration}

The service is registered in the ServiceRegistry with the interface template \texttt{generic\_\allowbreak{}https}, policy \texttt{CERT\_\allowbreak{}AUTH}, access address \texttt{certificate-\allowbreak{}authority}, port 8448 and base path \texttt{/\allowbreak{}certificate-\allowbreak{}authority}. The \texttt{operations} property of the interface lists the operations below with their method and path relative to the base path (path parameters are placeholders such as \texttt{\{id\}} that the consumer fills in):

\noindent\begin{longtable}{| p{5.2cm} | p{1.6cm} | p{8.4cm} |} \hline
\rowcolor{gray!33} Operation & Method & Path \\ \hline \endhead
\texttt{sign} & POST & \texttt{/\allowbreak{}sign} \\ \hline
\end{longtable}

\section{Service Operations}
\label{sec:operations}

The interfaces of the \texttt{certificateSigning} service, its operations, data models and implementation are provided below.
In particular, each subsection first names the HTTP method and path used to call the operation, after which it names the abstract operation from the \texttt{certificateSigning} SD document, as well as input and output types.

Every request needs mutual TLS with a system or operator certificate of the cloud and \texttt{Authorization: Bearer IDENTITY-TOKEN//<token>}; the token is verified with Authentication and must belong to the system named by the certificate. Request and response bodies are \texttt{application/json} unless stated otherwise.
Errors are answered with \texttt{\{\"error\": \"<text>\"\}} and the status codes \texttt{400 Bad Request} (invalid input), \texttt{401 Unauthorized} (no valid identity), \texttt{403 Forbidden} (caller not permitted), \texttt{404 Not Found}, \texttt{500 Internal Server Error}, \texttt{502 Bad Gateway} (a system it depends on failed) and \texttt{503 Service Unavailable} (overloaded).

\osubsection{sign}{POST}{/\allowbreak{}certificate-authority/\allowbreak{}sign}{\mref[Certificate\allowbreak{}Signing\allowbreak{}Request]{CertificateSigningRequest}}{\mref{CertificateSigningResult}}

Signs a CSR for the requester's permitted profile and records the certificate.

A successful call returns \texttt{201 Created} with the output in the body.

\begin{lstlisting}[label={lst:sign},caption={An \oref{sign} invocation.}]
POST /certificate-authority/sign HTTP/1.1
Host: certificate-authority:8448
Authorization: Bearer IDENTITY-TOKEN//<token>
Content-Type: application/json

{
  "encodedCSR": "-----BEGIN CERTIFICATE REQUEST-----\\n...",
  "profile": "sy",
  "addresses": [
    "sensor1"
  ],
  "validAfter": "2026-10-22T12:00:00Z",
  "validBefore": "2026-10-22T12:00:00Z"
}
\end{lstlisting}

\begin{lstlisting}[label={lst:sign-resp},caption={An \oref{sign} response.}]
{
  "id": 42,
  "certificateChain": [
    "<leaf Base64 DER>",
    "<CA Base64 DER>"
  ],
  "commonName": "Device1.TestCloud.Company.arrowhead.eu",
  "profile": "SYSTEM",
  "serialNumber": "4189327123456789",
  "validAfter": "2026-10-22T12:00:00Z",
  "validBefore": "2026-10-22T12:00:00Z"
}
\end{lstlisting}

\section{Data Models}
\label{sec:model}

Here, all data objects that can be part of the service calls associated with this service are listed in alphabetic order.
Note that each subsection, which describes one type of object, begins with the \textit{struct} keyword, which is meant to denote a JSON \pref{Object} that must contain certain fields, or names, with values conforming to explicitly named types.
Fields that are not needed may be omitted or \texttt{null} in requests; empty fields are omitted in responses.
As a complement to the primary types defined in this section, there is also a list of secondary types in Section \ref{sec:model:primitives}, which are used to represent things like hashes, identifiers and texts.

\msubsection{struct}{CertificateSigningRequest}




\noindent\begin{tabularx}{\textwidth}{| >{\raggedright\arraybackslash}p{3.9cm} | >{\raggedright\arraybackslash\small}p{5.3cm} | X |} \hline
\rowcolor{gray!33} Object Field & Value Type & Description \\ \hline
"encoded\allowbreak{}CSR" & \pref{String} & PEM PKCS\textbackslash{}\#10 request or Base64 DER (alias \texttt{csr}). \\ \hline
"profile" & \pref{String} & \texttt{on}, \texttt{de}, \texttt{sy} or \texttt{op}; default the CSR dnQualifier, else \texttt{sy}. Must be allowed for the caller. \\ \hline
"addresses" & \pref{Array}$<$\allowbreak{}\pref{String}$>$ & DNS names and IP addresses for the subject alternative name (at most 16); default those of the CSR. \\ \hline
"valid\allowbreak{}After" & \pref{DateTime} & Start of validity, ISO 8601; default now minus one minute. \\ \hline
"valid\allowbreak{}Before" & \pref{DateTime} & End of validity; default start plus the profile maximum (24 h for \texttt{on}, 365 days otherwise), never beyond the CA certificate. \\ \hline
\end{tabularx}
