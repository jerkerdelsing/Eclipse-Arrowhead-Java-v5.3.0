\section{Overview}
\label{sec:overview}

This document describes the \texttt{qualityEvaluation} service interface of the DeviceQoSEvaluator system, which provides quality-of-service evaluation of candidate providers from measurements of the devices hosting them (round-trip time, CPU load, memory use, network load).

It's implemented using protocol, encoding as stated in below table:
\begin{table}[ht!]
  \centering
  \begin{tabular}{|l|l|l|}
    \hline
    \rowcolor{gray!33} Profile type & Type & Version \\ \hline
    Transfer protocol & HTTP & 1.1 \cite{rfc9112} \\ \hline
    Data encryption & TLS & 1.3 \cite{rfc8446}, 1.2 \cite{rfc5246} \\ \hline
    Encoding & JSON & RFC 8259 \cite{rfc8259} \\ \hline
    Compression & N/A & - \\ \hline
    Semantics & N/A & - \\ \hline
    Ontology & N/A & - \\ \hline
  \end{tabular}
  \caption{Communication and semantics details used for the \texttt{qualityEvaluation} service interface}
  \label{tab:comunication_semantics_profile}
\end{table}

This document provides the Interface Design Description IDD to the \textit{qualityEvaluation -- Service Description} document \cite{dqe-qualityEvaluation-sd}.
For further details about how this service is meant to be used, please consult that document.

The rest of this document describes how to realize the \texttt{qualityEvaluation} service
interface in detail. Both in terms of its operations (Section \ref{sec:operations}) and its information model (Section \ref{sec:model}).

\subsection{Interface registration}

The service is registered in the ServiceRegistry with the interface template \texttt{generic\_\allowbreak{}https}, policy \texttt{CERT\_\allowbreak{}AUTH}, access address \texttt{device-\allowbreak{}qos-\allowbreak{}evaluator}, port 8472 and base path \texttt{/\allowbreak{}deviceqosevaluator/\allowbreak{}qualityevaluation}. The \texttt{operations} property of the interface lists the operations below with their method and path relative to the base path (path parameters are placeholders such as \texttt{\{id\}} that the consumer fills in):

\noindent\begin{longtable}{| p{5.2cm} | p{1.6cm} | p{8.4cm} |} \hline
\rowcolor{gray!33} Operation & Method & Path \\ \hline \endhead
\texttt{filter} & POST & \texttt{/\allowbreak{}filter} \\ \hline
\texttt{sort} & POST & \texttt{/\allowbreak{}sort} \\ \hline
\end{longtable}

\section{Service Operations}
\label{sec:operations}

The interfaces of the \texttt{qualityEvaluation} service, its operations, data models and implementation are provided below.
In particular, each subsection first names the HTTP method and path used to call the operation, after which it names the abstract operation from the \texttt{qualityEvaluation} SD document, as well as input and output types.

All operations require the requester's identity, presented according to the provider's authentication policy: the client certificate (mutual TLS) and, with the \texttt{outsourced} policy, \texttt{Authorization: Bearer IDENTITY-TOKEN//<token>}; systems holding the Authentication secret key send \texttt{Bearer AUTHENTICATOR-KEY//<system>//<hash>}, and with the \texttt{declared} policy \texttt{Bearer SYSTEM//<system>} is sent. Request and response bodies are \texttt{application/json} unless stated otherwise.
Errors are answered with an \mref{ErrorMessage} body and the status codes \texttt{400 Bad Request} (invalid parameter), \texttt{401 Unauthorized} (missing or invalid identity), \texttt{403 Forbidden} (not permitted, e.g. by the management, authorization or blacklist filter), \texttt{404 Not Found}, \texttt{408 Request Timeout}, \texttt{423 Locked}, \texttt{500 Internal Server Error} and \texttt{503 Service Unavailable} (a system it depends on failed).

\osubsection{filter}{POST}{/\allowbreak{}deviceqosevaluator/\allowbreak{}qualityevaluation/\allowbreak{}filter}{\mref{QoSEvaluationRequest}}{\mref[Qo\allowbreak{}SEvaluation\allowbreak{}Filter\allowbreak{}Response]{QoSEvaluationFilterResponse}}

Returns the providers that meet the threshold of the weighted metrics, and the dropped ones.

A successful call returns \texttt{200 OK} with the output in the body.

\begin{lstlisting}[label={lst:filter},caption={An \oref{filter} invocation.}]
POST /deviceqosevaluator/qualityevaluation/filter HTTP/1.1
Host: device-qos-evaluator:8472
Authorization: Bearer IDENTITY-TOKEN//<token>
Content-Type: application/json

{
  "providers": [
    "TemperatureSensor"
  ]
}
\end{lstlisting}

\begin{lstlisting}[label={lst:filter-resp},caption={An \oref{filter} response.}]
{
  "passedProviders": [
    "string"
  ],
  "droppedProviders": [
    "string"
  ]
}
\end{lstlisting}

\osubsection{sort}{POST}{/\allowbreak{}deviceqosevaluator/\allowbreak{}qualityevaluation/\allowbreak{}sort}{\mref{QoSEvaluationRequest}}{\mref[Qo\allowbreak{}SEvaluation\allowbreak{}Sort\allowbreak{}Response]{QoSEvaluationSortResponse}}

Returns the providers ordered by the weighted metrics, best first.

A successful call returns \texttt{200 OK} with the output in the body.

\begin{lstlisting}[label={lst:sort},caption={An \oref{sort} invocation.}]
POST /deviceqosevaluator/qualityevaluation/sort HTTP/1.1
Host: device-qos-evaluator:8472
Authorization: Bearer IDENTITY-TOKEN//<token>
Content-Type: application/json

{
  "providers": [
    "TemperatureSensor"
  ]
}
\end{lstlisting}

\begin{lstlisting}[label={lst:sort-resp},caption={An \oref{sort} response.}]
{
  "sortedProviders": [
    "string"
  ]
}
\end{lstlisting}

\section{Data Models}
\label{sec:model}

Here, all data objects that can be part of the service calls associated with this service are listed in alphabetic order.
Note that each subsection, which describes one type of object, begins with the \textit{struct} keyword, which is meant to denote a JSON \pref{Object} that must contain certain fields, or names, with values conforming to explicitly named types.
Fields that are not needed may be omitted or \texttt{null} in requests; empty fields are omitted in responses.
As a complement to the primary types defined in this section, there is also a list of secondary types in Section \ref{sec:model:primitives}, which are used to represent things like hashes, identifiers and texts.
