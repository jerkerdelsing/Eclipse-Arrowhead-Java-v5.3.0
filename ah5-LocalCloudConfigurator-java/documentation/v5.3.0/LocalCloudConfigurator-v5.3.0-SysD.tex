\section{Overview}
\label{sec:overview}

This document describes the LocalCloudConfigurator system. LocalCloudConfigurator designs and fills one existing, provisioned Java Arrowhead local cloud: from a trusted component catalog it derives dependency-ordered plans, keeps saved designs, and executes reviewed plans through a host worker that checks every step again.

\subsection{Significant Prior Art}
\label{sec:prior_art}

It ports the approach of the primary Go LocalCloudConfigurator (catalog, planner, reviewed plans, independent executor checks). Until November 2026 the Java version was a plain JDK HTTP server on port 8097 with file state, a shared operator token and a host worker on 8098; it was not an Arrowhead system.

\subsection{How This System Is Meant to Be Used}
\label{sec:use}

The operator works in the graphical editor of LocalCloudManager (view \emph{LC / Local cloud configuration}). LocalCloudManager consumes \texttt{local\allowbreak{}Cloud\allowbreak{}Configuration} through orchestration with its own certificate and identity token: it reads the catalog and the live status, saves designs, asks for a plan and applies the reviewed plan by its hash. LocalCloudConfigurator rebuilds the plan against the current runtime, and the host worker rebuilds and checks it once more before it runs the catalogued Compose actions.

\subsection{System functionalities and properties}
\label{sec:properties}

\subsubsection{Functional properties of the system}

\begin{itemize}
  \item Trusted component catalog (\texttt{catalogs/\allowbreak{}javacloud.\allowbreak{}json}): components with their Compose services, owned databases, dependencies, provisioning and policy scripts, protected components and the default core.
  \item Plans: the default core plus the selected components and their dependencies, in dependency order (provision, start, policy), explicit stops in reverse order and an optional non-mutating verification; running services are not recreated unless \texttt{reapply} is set.
  \item Reviewed deployments: a plan is applied only if its hash still matches a freshly built plan; one deployment at a time; step results reported per step; interrupted deployments are marked failed and never replayed.
  \item Saved designs (selections and graphical layout) with revision checks; saving never changes the runtime.
  \item Execution backends: the host worker over mutual TLS (direct, default) or the retained ColonyOS workflows (legacy).
  \item \texttt{general\allowbreak{}Management} (logs, configuration) and native sysMonitor observations.
\end{itemize}

The host worker has its own properties (\texttt{lcc.\allowbreak{}worker.\allowbreak{}*}), described in the SysDD.

\subsubsection{Data stored by the system}

Private MySQL schema \texttt{ah\_\allowbreak{}localcloudconfigurator}: saved designs, submitted deployments with the last reported state and step results, the active-deployment record and the log table. The host worker keeps its own file state (per-step results, its active-deployment marker) under \texttt{\textasciitilde/\allowbreak{}.local/\allowbreak{}share/\allowbreak{}JavaLocalCloudConfigurator/}.

\subsubsection{Non functional properties}

Deployments are serialized (one at a time). Status reads are cached for 2 s for display; plan and apply always read the runtime afresh. Interruption is not a transactional rollback: completed steps remain applied.

\subsubsection{Stateful or stateless}

Stateful (designs and deployment records in MySQL; worker file state).

\subsection{Important Delimitations}
\label{sec:delimitations}

The target is an existing, provisioned Java cloud: components are limited to the images, services and scripts of the catalog; arbitrary images, commands or secrets are not accepted. Starts use \texttt{-{}-no-deps -{}-no-build -{}-pull never}. The default core, its infrastructure and protected components cannot be stopped. The catalog and its scripts are trusted host-administrator inputs.

\section{Security}
\label{sec:security}

LocalCloudConfigurator is a Java-Spring support system. Its only connector (8492) uses HTTPS with mutual TLS and the X.509 certificate following the Arrowhead certificate profile (\texttt{LocalCloudConfigurator.<Cloud>.<Organization>.arrowhead.eu}).

\subsection{Security model}

\begin{itemize}
  \item \textbf{Protocols:} HTTPS (TLS 1.3 and 1.2) with mutual TLS on 8492 and to the host worker; AMQP over TLS for \texttt{sysMonitor}; TLS to its database (\texttt{verify-\allowbreak{}full}).
  \item \textbf{Security profile:} the common security profile guard refuses insecure settings unless the \texttt{development} profile is selected explicitly.
  \item \textbf{Callers:} client certificate and identity token of the same system; every \texttt{local\allowbreak{}Cloud\allowbreak{}Configuration} operation needs Sysop, \texttt{lcc.\allowbreak{}api.\allowbreak{}whitelist} or a ConsumerAuthorization grant of that operation (LocalCloudManager); \texttt{general\allowbreak{}Management} is Sysop only. There is no shared operator token.
  \item \textbf{Host worker:} mutual TLS on host loopback only; the configurator presents its LocalCloudConfigurator certificate and accepts only a worker certificate named \texttt{LocalCloudConfiguratorWorker}; the worker accepts only clients named \texttt{LocalCloudConfigurator}; both check the chain against the cloud truststore and, when configured, the CRL.
  \item \textbf{Execution:} the worker trusts only its own catalog; it rebuilds the reviewed plan, checks claimed ownership, step kind, script and catalog hash, runs argument lists (no shell interpolation), bounds and redacts command output.
  \item \textbf{Data protection:} private schema with a DML-only account; secrets as Compose file secrets; read-only root filesystem, UID 10001.
\end{itemize}

For the Arrowhead certificate profile see github.com/eclipse-arrowhead/documentation.
