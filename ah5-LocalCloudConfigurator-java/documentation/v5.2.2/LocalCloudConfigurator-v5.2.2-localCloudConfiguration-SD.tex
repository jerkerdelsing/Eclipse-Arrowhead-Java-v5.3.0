\section{Overview}
\label{sec:overview}

This document describes the \texttt{local\allowbreak{}Cloud\allowbreak{}Configuration} service, which lets a consumer read the component catalog and the runtime state of a local cloud, keep designs, review plans and apply them. It is produced by the LocalCloudConfigurator system \cite{lcc-sysd} in service version 1.0.0.

The rest of this document is organized as follows.
In Section \ref{sec:operations}, we describe the abstract message operations provided by the service.
In Section \ref{sec:model}, we end the document by presenting the data types used by the mentioned operations.
The concrete interface is specified in the HTTP/TLS/JSON IDD \cite{lcc-localCloudConfiguration-http-idd}.

\subsection{Significant Prior Art}

The operations are those of the earlier operator API of the Java LocalCloudConfigurator (paths below \texttt{/api}), now offered as an Arrowhead service.

\subsection{How This Service Is Meant to Be Used}

LocalCloudManager, the consumer, shows the catalog and the live status in its graphical editor, saves designs, asks for a plan, shows it to the operator and applies it by its hash after confirmation; it then follows the deployment step by step.

\subsection{Important Delimitations and Dependencies}
\label{sec:delimitations}

Every operation needs an authenticated caller and Sysop, the configurator's whitelist or a ConsumerAuthorization grant of that operation. A plan is applied only while its hash matches a plan built afresh; one deployment runs at a time. Saving or deleting a design never changes the runtime. Completed steps of a failed deployment remain applied.

\label{sec:operations}

This section describes the operations of the \texttt{local\allowbreak{}Cloud\allowbreak{}Configuration} service.
Each subsection names an abstract operation, an input type and an output type, in that order.
All abstract data types named in this section are defined in Section \ref{sec:model}.

\osubsection{catalog}{}{\mref{Catalog}}

The component catalog of the cloud.

\osubsection{status}{}{\mref{Status}}

Running Compose services and the state (\texttt{running}, \texttt{partial}, \texttt{stopped}) of each component (cached 2 s).

\osubsection{plan}{\mref{PlanRequest}}{\mref{PlanResponse}}

Builds a plan against the current runtime; returns it with its hash.

\osubsection{submit-deployment}{\mref{ApplyRequest}}{\mref{DeploymentAccepted}}

Applies a reviewed plan if its hash still matches a fresh plan and no other deployment is running.

\osubsection{get-deployment}{\pref{Identifier}}{\mref{Deployment}}

State and step results of a submitted deployment (identifier appended to the path); the report is stored.

\osubsection{list-configurations}{}{\mref{ConfigurationList}}

Saved designs (up to 1000), sorted by name.

\osubsection{create-configuration}{\mref{ConfigurationDraft}}{\mref{Configuration}}

Saves a new design (revision 1).

\osubsection{get-configuration}{\pref{Identifier}}{\mref{Configuration}}

One saved design.

\osubsection{update-configuration}{\mref{ConfigurationDraft}}{\mref{Configuration}}

Replaces a design when \texttt{expectedRevision} matches; the revision is incremented.

\osubsection{remove-configuration}{\mref{RevisionCheck}}{\mref{Removal}}

Deletes a design when \texttt{expectedRevision} matches; the runtime is unchanged.
