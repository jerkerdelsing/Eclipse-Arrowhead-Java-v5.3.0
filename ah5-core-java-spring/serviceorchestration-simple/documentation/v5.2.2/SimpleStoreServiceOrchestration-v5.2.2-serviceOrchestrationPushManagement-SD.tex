\section{Overview}
\label{sec:overview}

This document describes the \texttt{service\allowbreak{}Orchestration\allowbreak{}Push\allowbreak{}Management} service, which provides operator management of push orchestration: subscriptions made on behalf of consumers, and triggering of push orchestration.
It is produced by the SimpleStoreServiceOrchestration system \cite{ssso-sysd} in service version 1.0.0.

The rest of this document is organized as follows.
In Section \ref{sec:operations}, we describe the abstract message operations provided by the service.
In Section \ref{sec:model}, we end the document by presenting the data types used by the mentioned operations.
The concrete interface is specified in the HTTP/TLS/JSON IDD \cite{ssso-serviceOrchestrationPushManagement-http-idd}. The MQTT binding is specified in the MQTT/TLS/JSON IDD \cite{ssso-serviceOrchestrationPushManagement-mqtt-idd}.

\subsection{Significant Prior Art}

Corresponds to the Arrowhead 4.x orchestration store push features.

\subsection{How This Service Is Meant to Be Used}

Operators and support systems (e.g. the Choreographer, Plant\allowbreak{}Description\allowbreak{}Engine) create subscriptions for target systems, query and remove them, and trigger the execution of subscriptions; the orchestrator then sends the results to the subscribers' notify interfaces.

\subsection{Important Delimitations and Dependencies}
\label{sec:delimitations}

Push notifications are sent by worker threads (\texttt{push.\allowbreak{}orchestration.\allowbreak{}max.\allowbreak{}thread}); delivery is best effort and its outcome is recorded in the orchestration history.

\section{Service Interface}
\label{sec:operations}

This section describes the interfaces to the \texttt{service\allowbreak{}Orchestration\allowbreak{}Push\allowbreak{}Management} service.
In particular, each subsection names an abstract operation, an input type and an output type, in that order.
The input type is named inside parentheses, while the output type is preceded by a colon.
Input and output types are only denoted when accepted or returned, respectively, by the interface in question.

All abstract data types named in this section are defined in Section \ref{sec:model}.

\osubsection{subscribe}{\mref[Orchestration\allowbreak{}Subscription\allowbreak{}List\allowbreak{}Request]{OrchestrationSubscriptionListRequest}}{\mref[Orchestration\allowbreak{}Subscription\allowbreak{}List\allowbreak{}Response]{OrchestrationSubscriptionListResponse}}

Creates subscriptions on behalf of target systems.

\osubsection{unsubscribe}{\pref{List}$<$\allowbreak{}\pref{Identifier}$>$}{}

Removes subscriptions by identifier.

\osubsection{trigger}{\mref{OrchestrationPushTrigger}}{\mref[Orchestration\allowbreak{}Push\allowbreak{}Job\allowbreak{}List\allowbreak{}Response]{OrchestrationPushJobListResponse}}

Note that each subsection, which describes one type of object, begins with the \textit{struct} keyword, which is used to denote a collection of named fields, each with its own data type.
As a complement to the explicitly defined types in this section, there is also a list of implicit primitive types in Section \ref{sec:model:primitives}, which are used to represent things like hashes and identifiers.
