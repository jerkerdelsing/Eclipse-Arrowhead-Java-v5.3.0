\section{Overview}
\label{sec:overview}

This document describes the \texttt{service\allowbreak{}Orchestration} service, which provides service orchestration: a consumer asks which provider it should use for a service, and receives the matching, authorized providers with the interfaces to call.
It is produced by the SimpleStoreServiceOrchestration system \cite{ssso-sysd} in service version 1.0.0.

The rest of this document is organized as follows.
In Section \ref{sec:operations}, we describe the abstract message operations provided by the service.
In Section \ref{sec:model}, we end the document by presenting the data types used by the mentioned operations.
The concrete interface is specified in the HTTP/TLS/JSON IDD \cite{ssso-serviceOrchestration-http-idd}. The MQTT binding is specified in the MQTT/TLS/JSON IDD \cite{ssso-serviceOrchestration-mqtt-idd}.

\subsection{Significant Prior Art}

Successor of the Arrowhead 4.x Orchestrator \texttt{orchestration} service (store-based and dynamic orchestration were options of one system; in 5.x they are two systems with the same service definition).

\subsection{How This Service Is Meant to Be Used}

A consumer calls \texttt{pull} with a service requirement and gets the results immediately. Alternatively it subscribes with \texttt{subscribe} and an endpoint; the orchestrator then pushes results when triggered, and \texttt{unsubscribe} ends the subscription.

\subsection{Important Delimitations and Dependencies}
\label{sec:delimitations}

Results come only from the orchestration store maintained with \texttt{service\allowbreak{}Orchestration\allowbreak{}Simple\allowbreak{}Store\allowbreak{}Management}; the ServiceRegistry, Consumer\allowbreak{}Authorization and other systems are not consulted. A result contains only the provider, service definition, version and instance identifier; the consumer must look up the interfaces in the ServiceRegistry. Only the flags \texttt{MATCHMAKING} and \texttt{ONLY\_\allowbreak{}PREFERRED} are supported; other request fields and flags are ignored and reported in the warnings.

\section{Service Interface}
\label{sec:operations}

This section describes the interfaces to the \texttt{service\allowbreak{}Orchestration} service.
In particular, each subsection names an abstract operation, an input type and an output type, in that order.
The input type is named inside parentheses, while the output type is preceded by a colon.
Input and output types are only denoted when accepted or returned, respectively, by the interface in question.

All abstract data types named in this section are defined in Section \ref{sec:model}.

  \end{tikzpicture}
  \caption{SysML-style block of the \texttt{service\allowbreak{}Orchestration} service and its operations.}
  \label{fig:SD}

The following interface operations are available.

\osubsection{pull}{\mref{OrchestrationRequest}}{\mref{OrchestrationResponse}}

Returns the store entries of the requester for the requested service definition in priority order; preferred providers first (\texttt{ONLY\_\allowbreak{}PREFERRED}: only them); with \texttt{MATCHMAKING} only the best entry per service definition.

\osubsection{subscribe}{\mref[Orchestration\allowbreak{}Subscription\allowbreak{}Request]{OrchestrationSubscriptionRequest}}{\pref{String}}

Creates (or replaces) a push subscription of the requester for itself; with \texttt{trigger=\allowbreak{}true} the orchestration is executed and pushed immediately. Returns the subscription identifier, 201 for a new subscription.

Optional parameter: \texttt{trigger}.

\osubsection{unsubscribe}{\pref{Identifier}}{}

Removes a subscription of the requester. Returns 200 if removed, 204 if it did not exist.
