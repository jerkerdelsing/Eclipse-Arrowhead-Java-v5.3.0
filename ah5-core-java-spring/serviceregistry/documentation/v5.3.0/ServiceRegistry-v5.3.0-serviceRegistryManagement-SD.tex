\section{Overview}
\label{sec:overview}

This document describes the \texttt{service\allowbreak{}Registry\allowbreak{}Management} service, which provides operator management of the whole ServiceRegistry content: devices, systems, service definitions, service instances and interface templates.
It is produced by the ServiceRegistry system \cite{sr-sysd} in service version 1.0.0.

The rest of this document is organized as follows.
In Section \ref{sec:operations}, we describe the abstract message operations provided by the service.
In Section \ref{sec:model}, we end the document by presenting the data types used by the mentioned operations.
The concrete interface is specified in the HTTP/TLS/JSON IDD \cite{sr-serviceRegistryManagement-http-idd}. The MQTT binding is specified in the MQTT/TLS/JSON IDD \cite{sr-serviceRegistryManagement-mqtt-idd}.

\subsection{Significant Prior Art}

Corresponds to the Arrowhead 4.x ServiceRegistry \texttt{mgmt} endpoints.

\subsection{How This Service Is Meant to Be Used}

Operators and authorized management systems (e.g. the onboarding procedure, LocalCloudManager, Dynamic\allowbreak{}Service\allowbreak{}Orchestration) query and edit registry records on behalf of other systems, and maintain the interface templates that service registrations are validated against.

\subsection{Important Delimitations and Dependencies}
\label{sec:delimitations}

Access is governed by the management policy of the ServiceRegistry (\texttt{management.\allowbreak{}policy}: \texttt{SYSOP\_\allowbreak{}ONLY}, \texttt{WHITELIST} or \texttt{AUTHORIZATION}); in the Arrowhead-test-cloud-java deployment it is a whitelist. Removing a device or system cascades to the records that depend on it as described per operation.

\section{Service Interface}
\label{sec:operations}

This section describes the interfaces to the \texttt{service\allowbreak{}Registry\allowbreak{}Management} service.
In particular, each subsection names an abstract operation, an input type and an output type, in that order.
The input type is named inside parentheses, while the output type is preceded by a colon.
Input and output types are only denoted when accepted or returned, respectively, by the interface in question.

All abstract data types named in this section are defined in Section \ref{sec:model}.
