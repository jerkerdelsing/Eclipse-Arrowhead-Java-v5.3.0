\section{Overview}
\label{sec:overview}

This document describes the \texttt{authorization\allowbreak{}Management} service interface of the ConsumerAuthorization system, which provides operator management of authorization policies at the management level, and bulk evaluation of authorization questions.

It's implemented using protocol, encoding as stated in below table:
\begin{table}[ht!]
  \centering
  \begin{tabular}{|l|l|l|}
    \hline
    \rowcolor{gray!33} Profile type & Type & Version \\ \hline
    Transfer protocol & HTTP & 1.1 \cite{rfc9112} \\ \hline
    Data encryption & TLS & 1.3 \cite{rfc8446}, 1.2 \cite{rfc5246} \\ \hline
    Encoding & JSON & RFC 8259 \cite{rfc8259} \\ \hline
    Compression & N/A & - \\ \hline
    Semantics & N/A & - \\ \hline
    Ontology & N/A & - \\ \hline
  \end{tabular}
  \caption{Communication and semantics details used for the \texttt{authorization\allowbreak{}Management} service interface}
  \label{tab:comunication_semantics_profile}
\end{table}

This document provides the Interface Design Description IDD to the \textit{authorizationManagement -- Service Description} document \cite{ca-authorizationManagement-sd}.
For further details about how this service is meant to be used, please consult that document.

The rest of this document describes how to realize the \texttt{authorization\allowbreak{}Management} service
interface in detail. Both in terms of its operations (Section \ref{sec:operations}) and its information model (Section \ref{sec:model}).

\subsection{Interface registration}

The service is registered in the ServiceRegistry with the interface template \texttt{generic\_\allowbreak{}https} (\texttt{generic\_\allowbreak{}http} when TLS is disabled), access port 8445 and base path \texttt{/\allowbreak{}consumerauthorization/\allowbreak{}authorization/\allowbreak{}mgmt}. The \texttt{operations} property of the interface lists the operations below with their method and path relative to the base path (path parameters are placeholders such as \texttt{\{id\}} that the consumer fills in):

\noindent\begin{longtable}{| p{5.2cm} | p{1.6cm} | p{8.4cm} |} \hline
\rowcolor{gray!33} Operation & Method & Path \\ \hline \endhead
\texttt{grant-\allowbreak{}policies} & POST & \texttt{/\allowbreak{}grant} \\ \hline
\texttt{revoke-\allowbreak{}policies} & DELETE & \texttt{/\allowbreak{}revoke} \\ \hline
\texttt{query-\allowbreak{}policies} & POST & \texttt{/\allowbreak{}query} \\ \hline
\texttt{check-\allowbreak{}policies} & POST & \texttt{/\allowbreak{}check} \\ \hline
\end{longtable}

\section{Service Operations}
\label{sec:operations}

The interfaces of the \texttt{authorization\allowbreak{}Management} service, its operations, data models and implementation are provided below.
In particular, each subsection first names the HTTP method and path used to call the operation, after which it names the abstract operation from the \texttt{authorization\allowbreak{}Management} SD document, as well as input and output types.

All operations require the requester's identity, presented according to the provider's authentication policy: the client certificate (mutual TLS) and, with the \texttt{outsourced} policy, \texttt{Authorization: Bearer IDENTITY-TOKEN//<token>}; systems holding the Authentication secret key send \texttt{Bearer AUTHENTICATOR-KEY//<system>//<hash>}, and with the \texttt{declared} policy \texttt{Bearer SYSTEM//<system>} is sent. Request and response bodies are \texttt{application/json}.
Errors are answered with an \mref{ErrorMessage} body and the status codes \texttt{400 Bad Request} (invalid parameter), \texttt{401 Unauthorized} (missing or invalid identity), \texttt{403 Forbidden} (not permitted, e.g. by the management or blacklist filter), \texttt{404 Not Found}, \texttt{408 Request Timeout}, \texttt{423 Locked}, \texttt{500 Internal Server Error} and \texttt{503 Service Unavailable} (a system it depends on failed).

\subsection{Primitives}
\label{sec:model:primitives}

As all messages are encoded using the JSON format \cite{rfc8259}, the following primitive constructs, part of that standard, become available.
Note that the official standard is defined in terms of parsing rules, while this list only concerns syntactic information.
