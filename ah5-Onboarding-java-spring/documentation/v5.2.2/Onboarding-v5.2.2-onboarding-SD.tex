\section{Overview}
\label{sec:overview}

This document describes the \texttt{onboarding} service, which provides the Arrowhead onboarding procedure: a device holding only an approved bootstrap certificate obtains its onboarding, device and system certificates and the identities of its systems.
It is produced by the Onboarding system \cite{onb-sysd} in service version 1.0.0.

The rest of this document is organized as follows.
In Section \ref{sec:operations}, we describe the abstract message operations provided by the service.
In Section \ref{sec:model}, we end the document by presenting the data types used by the mentioned operations.
The concrete interface is specified in the HTTP/TLS/JSON IDD \cite{onb-onboarding-http-idd}.

\subsection{Significant Prior Art}

Follows Bicaku et al., Interacting with the Arrowhead Local Cloud: On-boarding Procedure (2018), and the v4.6.2 onboarding controller.

\subsection{How This Service Is Meant to Be Used}

Step 1: with the bootstrap certificate, \texttt{onboard-\allowbreak{}with-\allowbreak{}csr} (or \texttt{onboard-\allowbreak{}with-\allowbreak{}name}) returns an onboarding certificate (\texttt{on}, at most 24 h). Step 2: with it, \texttt{onboard-\allowbreak{}device} returns the device certificate (\texttt{de}) and registers the device. Step 3: with the device certificate, \texttt{onboard-\allowbreak{}system} returns a system certificate (\texttt{sy}) and identity password for each approved system. The systems then register and orchestrate as usual. \texttt{offboard-\allowbreak{}device} withdraws everything.

\subsection{Important Delimitations and Dependencies}
\label{sec:delimitations}

Only devices approved with \texttt{onboarding\allowbreak{}Management} (by bootstrap-certificate fingerprint) are accepted, and only the onboarding and device certificates issued last, while the Certificate\allowbreak{}Authority reports them GOOD. Onboarding holds no CA key; the Certificate\allowbreak{}Authority signs. Prefer CSRs: without one Onboarding generates the key and returns it once.

\section{Service Interface}
\label{sec:operations}

This section describes the interfaces to the \texttt{onboarding} service.
In particular, each subsection names an abstract operation, an input type and an output type, in that order.
The input type is named inside parentheses, while the output type is preceded by a colon.
Input and output types are only denoted when accepted or returned, respectively, by the interface in question.

All abstract data types named in this section are defined in Section \ref{sec:model}.

The following interface operations are available.

\osubsection{onboard-with-name}{\mref{NameRequest}}{\mref{Response}}

Step 1 without CSR: Onboarding generates a key pair and returns the onboarding certificate with its private key (once).

\osubsection{onboard-with-csr}{\mref{CsrRequest}}{\mref{Response}}

Step 1: signs the device's onboarding certificate (\texttt{on}) from its CSR; returns the chain and the registry descriptors.

\osubsection{onboard-device}{\mref{DeviceRequest}}{\mref{DeviceResponse}}

Step 2, with the onboarding certificate: signs the device certificate (\texttt{de}) and registers the device in the ServiceRegistry.

\osubsection{onboard-system}{\mref{SystemRequest}}{\mref{SystemResponse}}

Step 3, with the device certificate: signs the system certificate (\texttt{sy}) of an approved system and creates its Authentication identity; returns the identity password once.

\osubsection{offboard-device}{}{\mref{OffboardingReport}}

With the device certificate: removes the device's systems, identities and registry entries, revokes the certificates and blacklists the systems.
