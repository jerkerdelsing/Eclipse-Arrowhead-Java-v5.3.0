\section{Overview}
\label{sec:overview}

This document describes the \texttt{time} service, which provides the current time of the local cloud with the configured time zone and an assessment whether the time can be trusted (offset to NTP below a threshold).
It is produced by the TimeManager system \cite{tim-sysd} in service version 1.0.0.

The rest of this document is organized as follows.
In Section \ref{sec:operations}, we describe the abstract message operations provided by the service.
In Section \ref{sec:model}, we end the document by presenting the data types used by the mentioned operations.
The concrete interface is specified in the HTTP/TLS/JSON IDD \cite{tim-time-http-idd}.

\subsection{Significant Prior Art}

Successor of the Arrowhead 4.6 TimeManager \texttt{time} service; the WebSocket push and \texttt{/\allowbreak{}echo} were removed.

\subsection{How This Service Is Meant to Be Used}

Systems that need a common or trusted time call \texttt{get-\allowbreak{}time} and check \texttt{trusted} before relying on it.

\subsection{Important Delimitations and Dependencies}
\label{sec:delimitations}

Trust is based on SNTP checks against \texttt{ntp.\allowbreak{}server.\allowbreak{}list}; the time is untrusted until the first check and while no server answers. With \texttt{service.\allowbreak{}authorization.\allowbreak{}enabled=\allowbreak{}true} every call is checked with Consumer\allowbreak{}Authorization.

\section{Service Interface}
\label{sec:operations}

This section describes the interfaces to the \texttt{time} service.
In particular, each subsection names an abstract operation, an input type and an output type, in that order.
The input type is named inside parentheses, while the output type is preceded by a colon.
Input and output types are only denoted when accepted or returned, respectively, by the interface in question.

All abstract data types named in this section are defined in Section \ref{sec:model}.

\section{Information Model}
\label{sec:model}

Here, all data objects that can be part of the \texttt{time} service are listed in alphabetic order.
Note that each subsection, which describes one type of object, begins with the \textit{struct} keyword, which is used to denote a collection of named fields, each with its own data type.
As a complement to the explicitly defined types in this section, there is also a list of implicit primitive types in Section \ref{sec:model:primitives}, which are used to represent things like hashes and identifiers.

\msubsection{struct}{TimeResponse}

Current time and its trust assessment.


\noindent\begin{tabularx}{\textwidth}{| >{\raggedright\arraybackslash}p{3.9cm} | >{\raggedright\arraybackslash\small}p{5.3cm} | X |} \hline
\rowcolor{gray!33} Field & Type & Description \\ \hline
epoch & \pref{Number} & Current time, seconds since 1970-01-01T00:00:00Z. \\ \hline
epoch\allowbreak{}Ms & \pref{Number} & Current time, milliseconds since 1970-01-01T00:00:00Z. \\ \hline
tz & \pref{String} & Configured IANA time zone (\texttt{time.\allowbreak{}timezone}). \\ \hline
dst & \pref{Boolean} & Whether daylight saving time is in effect in that zone. \\ \hline
trusted & \pref{Boolean} & Whether the clock offset to NTP is below \texttt{time.\allowbreak{}offset.\allowbreak{}threshold}. \\ \hline
offset\allowbreak{}Ms & \pref{Number} & Last measured offset to the NTP server in milliseconds; null before the first check. \\ \hline
time\allowbreak{}Source & \pref{String} & NTP server of the last successful check. \\ \hline
last\allowbreak{}Check\allowbreak{}Time & \pref{DateTime} & Time of the last successful NTP check. \\ \hline
\end{tabularx}
